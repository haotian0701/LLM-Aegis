# 阶段 6：验收与结果可见性（首批）

## 本批实现

- 增加参数化验收矩阵，覆盖普通内容、邮箱、电话、IP、API Key、Secret、混合类别优先级及企业机密。假模型记录实际收到的消息，断言 `MASK_CLOUD` 收到占位符而非原文，`BLOCK` 没有模型调用，`LOCAL` 模拟与 `CLOUD` 的实际目的地和响应头一致。
- 演示页在每次请求结束后按请求 ID 读取审计摘要，并可手动重新查询。页面展示命中类别、检测状态、语义调用状态、脱敏状态、模型调用状态和审计结果。
- 新增仅在本机 `demo` 模式可用的 `GET /demo/audit/{request_id}`。它只接受当前进程生成的浏览器 token，且只读取该演示主体自己的记录。响应只含上述状态元数据，不含消息、Prompt HMAC 或凭据。
- PostgreSQL 审计读取使用现有字段，无迁移；集成测试验证按主体隔离。

## 验收矩阵

| 输入类别 | 预期策略 | 假模型应收到 | 审计脱敏状态 |
| --- | --- | --- | --- |
| 普通内容 | `CLOUD` | 原文 | 未执行 |
| 邮箱、国际电话、IP | `MASK_CLOUD` | 对应占位符 | `SUCCEEDED` |
| API Key、Secret | `BLOCK` | 无请求 | 未执行 |
| 邮箱 + API Key | `BLOCK` | 无请求 | 未执行 |
| 企业机密 | `LOCAL` | 原文，模拟 Provider | 未执行 |

会话连续性、模型故障、审计故障、历史消息和工具参数脱敏，沿用阶段 3 至 5 的专项测试。页面中的 `masking_status=SUCCEEDED` 表示出站前脱敏校验和模型外发意图审计已经完成；假模型测试进一步核对实际出站消息。
